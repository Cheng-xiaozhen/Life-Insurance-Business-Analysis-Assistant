## 按需加载

1. 根据任务选择上表中最直接相关的文档，先定位标题，再读取对应章节。
2. 只有遇到字段含义、业务要求或输出风格等具体问题时，才补读相关文档；不因文档之间有关联就全部加载。
3. 涉及当前执行行为时，沿技术文档中的代码入口核对实现；同一任务内已读且未变更的内容无需重复加载。

常见任务的最小阅读范围：

| 任务 | 首先读取 | 需要时补读 |
| --- | --- | --- |
| 了解服务整体职责 | AI Service 设计说明 | 对应功能技术说明 |
| 修改问答节点或执行路线 | 智能问答功能的“LangGraph节点定义”“LangGraph工作流” | 模板说明的“单个场景模板” |
| 排查聊天确认、状态或进度 | 智能问答功能的“聊天入口附加节点”“State 与调用边界”“条件路由与暂停恢复” | 需求文档的“模块 A：智能问答” |
| 修改场景配置 | 模板说明的“单个场景模板” | 智能问答功能中的模板加载与步骤执行说明 |
| 设计报告生成 | 报告生成功能的节点与工作流设计、模板说明的“完整报告模板” | AI Service 设计说明的“报告生成”、需求文档的“模块 B：报告生成” |
| 调整结论或报告表达 | 月度分析报告示例 | 模板说明的“写作风格与格式要求” |
| 处理知识导入或模板管理需求 | 需求文档的“模块 C：知识管理” | 模板说明中对应的模板类型 |

需求文档描述产品目标，不代表功能均已实现；技术说明用于理解实现，当前行为仍需以代码和验证结果确认。报告示例用于参考表达，不作为实时数据或新增业务规则的来源。文档之间有差异时，应明确区分需求、设计和实现，不自行将三者合并为既有能力。

## 索引维护

新增、重命名或删除文档时，同步更新本索引中的链接、用途和阅读入口；文档从空白补充为正文后，更新其状态。索引只保留定位信息，具体字段、流程和规则在对应文档中维护。
